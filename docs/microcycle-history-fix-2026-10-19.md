# Historical execution at a microcycle boundary

## Failure and scope

The v48 whole-microcycle planner can raise `KeyError` when the last real key
session precedes the visible draft but belongs to its anchored microcycle.
`segment_keys` covers the whole cycle; `actual_by_day` only covers future
schedule slots. The catch-up check incorrectly indexes the latter with the
historical execution date. The observed staging failure on 19 October requested
18 October this way. Both manual refresh and automatic adaptation use this path.

v49 uses execution dates from the complete planning history for this one check.
Draft-local slot occupancy, quotas, spacing, dose rules and component accounting
keep their existing behavior. A previously reserved, unexecuted future key still
suppresses extra catch-up in its cycle. A real historical key does not masquerade
as an unexecuted reservation. Engine versioning invalidates prior computation
keys and records the correction's provenance.

## Validation

Full-engine regressions cover a real key one and two days before the draft, a
key in the preceding cycle, and a future reservation in the same cycle. They
check the two-day spacing rule, valid catch-up, absence of duplicate catch-up,
unchanged source history, readiness dosing and rolling budgets. The one- and
two-day history cases reproduce the original exception before the fix.

Staging acceptance: deploy the tested commit to API and worker; verify the new
commit is live, refresh the draft, and check that a new proposal is persisted
without the exception. Review status must remain caller-controlled; do not
approve a training plan as part of this technical correction. Confirm worker
adaptation no longer defers on this error for the tested input.

## Recovery and limits

No schema migration, deletion or history rewrite is needed. Revert the fix
commit and redeploy API and worker if necessary. Existing approved plans and
immutable revisions remain available. A rollback reintroduces the known v48
failure; it does not delete proposals generated by v49.

The 213.85-minute introductory variant, 40-second building Z5 dose, reservation
consistency and read/JSON overhead remain separate audit findings. This change
does not resolve or redefine their methodological rules.
